# Where Am I?

A command can be spelled correctly and still fail because the shell looked for a file in the wrong place.
Before you create, move, or delete anything, learn to answer three questions: where am I, what is here, and how do I get somewhere else?

Your graphical file manager answers these questions with windows, icons, and an address bar.
The shell answers them with directories and paths.
Both describe the same files on the same disk.
You are learning a second way to navigate, not entering a separate collection of documents.

This chapter changes your shell's current directory, but it does not create, rename, move, or delete files.
Use a normal session without administrator privileges.
The PowerShell examples work in Windows PowerShell 5.1 and PowerShell 7; Windows-specific paths are labeled.

We start with vocabulary: how directories are organized and how a path names one of them.
Then we use that vocabulary to ask the shell where you are, list what is there, and move somewhere else.

## Directories Form a Tree

A **directory** is a folder that can contain files and other directories.
A directory inside another is its **child** or **subdirectory**.
The containing directory is its **parent**.
Directories with the same parent are **siblings**.

Every directory except one has a parent, so the directories on a disk form a tree.
The directory at the top, the one with no parent, is the **root**.

Here is a small part of one tree.
This is a diagram, not a command or a set of folders you need to create:

```{.text .no-copy}
/home/student/
      +-- projects/
      |   +-- game/
      |   |   +-- notes.txt
      |   +-- website/
      +-- downloads/
```

Read it from the top down.
`projects` and `downloads` are children of `/home/student`.
`projects` is the parent of `game` and `website`, so those two directories are siblings.
`notes.txt` is a file inside `game`.
The trailing slashes in this diagram identify directories; they are not part of their names.

The diagram starts below the root.
`student` is inside `home`, and `home` is inside the root, which UNIX-style systems write as `/`.

One directory in the tree is your **home directory**: the usual starting place for your own files and many personal settings.
In the diagram, home is `/home/student`.
On macOS it would be `/Users/student`, and on Windows `C:\Users\student`.
Home is somewhere below the root, never the root itself.
Do not confuse the two.

## A Path Names a Place in the Tree

A **path** identifies a file or directory by listing the directories you pass through to reach it.
A separator character sits between the names.
UNIX-style paths on Linux and macOS use `/`.
Windows paths use `\`.
PowerShell on macOS or Linux uses that system's `/` paths; installing a different shell does not change how the operating system names its files.

An **absolute path** starts at a root and names every directory down to the target.
It identifies the same place no matter where you are.
`/home/student/projects/game/notes.txt` is the absolute path to the file in the diagram.
The same layout under a Windows home directory would be `C:\Users\student\projects\game\notes.txt`.
On Windows the root is a drive root such as `C:\`; we return to drives later in this chapter.

An absolute path is not automatically portable to another computer.
The username, drive, directory layout, or file may differ.
Do not copy another person's home directory from an example; use the one your shell reports.

A path can also start from where you already are.
That form depends on the idea of a current directory, so we define that next.

## Find Your Current Directory

The **current directory**, also called the **working directory**, is the directory your shell is working in right now.
It belongs to your shell session.
Two terminal tabs can be looking at different directories on the same computer, and changing directories in one tab does not affect the other.

Your prompt may display the current directory, but it can abbreviate or omit it.
Ask the shell directly when you need to know.

### Bash/zsh

`pwd` means **print working directory**:

```session
$ pwd
```

It prints an absolute path, perhaps `/home/student` on Linux or `/Users/student` on macOS.
Your path reflects your account and where this session started. [@BashNavigation; @ZshBuiltins]

### PowerShell

`Get-Location` shows your current directory:

```session
$ Get-Location
```

Look at the `Path` field in the output.
On Windows it might be `C:\Users\student`; PowerShell on macOS or Linux shows that system's path. [@PowerShellGetLocation]

### Command Prompt

In Command Prompt, `cd` with no argument displays the current drive and directory:

```session
$ cd
```

It might display `C:\Users\student`. [@WindowsCd]

::: {.tip}
**Wut:** Bare `cd` does different things in different shells.
In Bash and zsh it takes you home; in Command Prompt it reports your current directory.
Check what a command does in the shell you are using.
:::

## Two Names Every Directory Has

Every directory contains two special names:

- `.` means the current directory itself.
- `..` means its parent.

The two dots in `..` are one name, not two separate arguments.
Because `.` and `..` exist in every directory, you can use them without knowing the directory's real name. [@AppleTerminalPaths; @WindowsPaths]

These two names are the start of a **relative path**: a path that begins at the current directory instead of a root.
A relative path may begin with `.`, with `..`, or simply with the name of a child.
Imagine that your current directory is `game` in the diagram above.
Read these paths without running anything:

| Target | UNIX-style relative path | Windows-style relative path |
|---|---|---|
| The file inside `game` | `notes.txt` or `./notes.txt` | `notes.txt` or `.\notes.txt` |
| The parent, `projects` | `..` | `..` |
| The sibling, `website` | `../website` | `..\website` |
| `downloads` under home | `../../downloads` | `..\..\downloads` |

Read the last row as "up to projects, up to home, down to downloads."
A relative path only means something together with a current directory.
If you change the current directory, the same relative path leads somewhere else, or nowhere.

Each kind of path has a use.
A relative path is convenient inside a project whose internal layout stays the same wherever it is copied.
An absolute path is unambiguous, but it ties the command to one machine's layout.

## What Is Here?

A directory listing shows the names inside a directory.
You met the listing commands in Chapter 2.
Here we give each one the path `.`, so the command states which directory it lists:

**Bash/zsh:**

```session
$ ls .
```

**PowerShell:**

```session
$ Get-ChildItem -LiteralPath .
```

**Command Prompt:**

```session
$ dir .
```

`-LiteralPath` tells `Get-ChildItem` to use the path exactly as written, without interpreting characters such as square brackets as wildcard patterns.
We use it throughout this chapter for that reason. [@PowerShellGetChildItem]

For these three commands, the current directory is also the default when you leave out the path.
`ls`, `Get-ChildItem`, and `dir` on their own list the same directory as the forms above; the explicit `.` just makes the location visible in the command. [@BashManual; @PowerShellGetChildItem; @WindowsDir]
Do not assume every command has this default: check its help when you are unsure.

Listing a directory does not change your current directory.
It answers "what is here?"; the next section answers "how do I get somewhere else?"

## Move Somewhere Else

Changing the current directory changes where every relative path starts.
Each shell has a command for it, and each command normally prints nothing when it succeeds.
Check your location afterward rather than treating silence as an error.
If the change fails, read the error before entering the next command.

### Go Home

Home is a reliable starting point because every account has one.
Do not hard-code another person's username from an example.
Ask your shell to use your account's home location.

#### Bash/zsh

`cd` means **change directory**.
With no argument, it takes you to the directory named by the `HOME` variable.
A **variable** stores a value the shell can use; here the value is a path.

```session
$ cd
$ pwd
```

Two other common ways to go home are `cd ~` and `cd "$HOME"`.
The **tilde**, `~`, is shell shorthand for your home directory when it appears at the start of an argument.
`$HOME` asks for the variable's value, and the surrounding double quotes keep that value together if it contains spaces. [@BashNavigation; @BashTilde; @ZshParameters]

Do not write `cd "~"` in Bash or zsh and expect the same result.
Quoting the tilde stops that shorthand from expanding, so the shell looks for a directory literally named `~`. [@BashTilde; @ZshQuoting]

#### PowerShell

`Set-Location` changes the current location.
`$HOME` supplies your home directory:

```session
$ Set-Location -LiteralPath $HOME
$ Get-Location
```

In a default session, `cd` is an alias for `Set-Location`, so `cd $HOME` is a shorter form.
We use the full name here to make the operation clear.
PowerShell passes the variable's string value as one argument, including any spaces in it. [@PowerShellSetLocation; @PowerShellAutomaticVariables]

#### Command Prompt

`%USERPROFILE%` supplies the path to your Windows user profile directory.
The percent signs are Command Prompt's syntax for reading this environment variable; they are not PowerShell syntax.

```session
$ cd /d "%USERPROFILE%"
$ cd
```

The `/d` option changes the active drive as well as the directory if necessary.
Keep the quotation marks so an account path containing spaces stays together. [@WindowsCd; @WindowsEnvironment]

Going home does not necessarily take you to the place where an application stores every document.
Folders such as Documents and Desktop can be redirected or synchronized elsewhere.
Use the actual location on your machine, not a guessed path.

### Go Up

From home, move to its parent with `..` and check where you arrived.
Then return home so the next example has a known starting point.
Enter the commands one at a time and inspect each location before continuing.

**Bash/zsh:**

```session
$ cd ..
$ pwd
$ cd
```

**PowerShell:**

```session
$ Set-Location -LiteralPath ..
$ Get-Location
$ Set-Location -LiteralPath $HOME
```

**Command Prompt:**

```session
$ cd ..
$ cd
$ cd /d "%USERPROFILE%"
```

### Go Down

To move into a child directory, supply its name instead of `..`.
First list your home directory and choose a directory you recognize.
In Bash/zsh, `ls -F .` marks directory names with a trailing `/`.
PowerShell's default filesystem listing marks directories with a `d` in the `Mode` column, and Command Prompt's usual `dir` listing labels them `<DIR>`.

For a child directory actually named `Downloads`, the commands are:

**Bash/zsh:**

```session
$ cd ./Downloads
$ pwd
```

**PowerShell:**

```session
$ Set-Location -LiteralPath .\Downloads
$ Get-Location
```

**Command Prompt:**

```session
$ cd .\Downloads
$ cd
```

Use the real spelling from your listing; that folder may have another name or location on your computer.
In a default configuration, leaving out the leading `./` or `.\` does the same thing.
We include it to show that the path starts from the current directory.

Return home before continuing.
The rest of the chapter assumes you start there.

## Roots and Drives

You have moved up, down, and home.
The top of the tree works differently on UNIX-style systems and on Windows, so it gets its own section.

### Linux and macOS

The root of the UNIX-style directory tree is `/`.
Other filesystems can be attached at directories within that tree, called **mount points**.
Everything reachable from your shell hangs off this one tree; you do not need a Windows-style drive letter for each device. [@PosixPathResolution]

Visit the root, list it, then return home:

```session
$ cd /
$ pwd
/
$ ls .
$ cd
```

Your listing depends on the operating system.
Do not change system files just because you can see their names.
The root directory `/` is also different from the administrative user named `root`.
You do not become an administrator by changing into `/`.

### Windows

Windows has one tree per drive instead of one tree for everything.
`C:\` is the root of drive `C:`.
Another drive might have a root such as `D:\`, but not every computer has a `D:` drive.
A drive letter can identify a volume or mapped location; it is not necessarily a separate physical disk.

In **PowerShell**, `Get-PSDrive` can show the filesystem drives available to the session:

```session
$ Get-PSDrive -PSProvider FileSystem
```

`-PSProvider FileSystem` limits the results to filesystem locations.
PowerShell also has providers that expose other data through directory-like paths; we are not exploring those here. [@PowerShellGetPSDrive]

If `D:\` exists on your computer, `Set-Location -LiteralPath D:\` moves there in PowerShell.
In **Command Prompt**, use `cd /d D:\` to change both drive and directory.
Without `/d`, `cd` can update another drive's remembered directory without switching your active drive. [@WindowsCd]

::: {.tip}
**Trap:** `C:\notes.txt` and `C:notes.txt` are different paths.
The first starts at the root of `C:`; the second depends on the remembered current directory for that drive.
Similarly, `\notes.txt` starts at the root of the current drive, not necessarily `C:`.
Use a drive letter followed by a backslash when you mean a fully specified drive root. [@WindowsPaths]
:::

Windows also supports network paths such as `\\server\share\folder`.
Recognize the form, but you do not need to connect to a network share for this chapter.

## Read Names Carefully

Navigation fails most often because the name you typed is not the name on disk.
Four details cause most of those mismatches: spaces, hidden entries, extensions, and capitalization.

### Names with Spaces

The quoting rules from Chapter 2 matter as soon as a directory name contains a space.
If an existing child directory were named `My Projects`, you could enter it as follows:

**Bash/zsh:**

```session
$ cd "./My Projects"
```

**PowerShell:**

```session
$ Set-Location -LiteralPath '.\My Projects'
```

**Command Prompt:**

```session
$ cd ".\My Projects"
```

These examples require that directory to exist; substitute a directory you actually have, or just read the examples for now.
The quote marks protect the space and are not part of the directory's name.
PowerShell's `-LiteralPath` additionally prevents wildcard interpretation of characters in the name.
Quotation and wildcard handling are separate issues. [@PowerShellSetLocation]

In Bash/zsh, `cd ./My\ Projects` is another way to protect that space.
Do not copy that backslash-escape spelling into a Windows path and expect it to mean the same thing; on Windows the backslash is the path separator.

### Hidden Does Not Mean Secret

Some entries are normally omitted from directory listings to reduce clutter.
On UNIX-style systems, a leading dot conventionally makes a name hidden from the default `ls` listing.
Names such as `.config` or `.git` are ordinary directory names with a leading dot, not the special `.` and `..` entries. [@CoreutilsListedFiles]

On Windows, hidden and system attributes affect what a default listing displays.
A leading dot alone is not the Windows hidden attribute.
Neither convention is an access-control mechanism.

From your home directory, compare an ordinary listing with one that includes hidden entries.
You already met these options in Chapter 2:

**Bash/zsh:**

```session
$ ls .
$ ls -a .
```

**PowerShell:**

```session
$ Get-ChildItem -LiteralPath .
$ Get-ChildItem -LiteralPath . -Force
```

**Command Prompt:**

```session
$ dir .
$ dir /a .
```

`-Force` and `/a` can reveal entries omitted from the normal display; they do not grant permission to read everything. [@PowerShellGetChildItem; @WindowsDir]
Do not delete an unfamiliar dotfile or hidden folder to tidy the listing.
It may hold configuration or information a tool needs.

### Read the Whole Filename

An **extension** is a suffix such as `.txt`, `.png`, or `.md` that conventionally indicates a file's type.
It is part of the filename.
`notes`, `notes.txt`, and `notes.txt.txt` are different names.

Graphical file managers can hide extensions even though the underlying names still contain them.
In Finder, the option is **Show all filename extensions** under **Finder > Settings > Advanced**.
File Explorer also has a setting to show file name extensions.
Enable it when comparing a graphical window with a shell listing. [@AppleFilenameExtensions; @WindowsFilenameExtensions]

The listing commands in this chapter show filename extensions, although a narrow display can wrap or truncate long names.
Do not copy a shortened display label and assume it is the complete name.

Changing a filename extension is not the same as converting the file's contents.
Calling a text document `picture.png` does not make it an image.
We will inspect and edit file contents in later chapters.

### Does Capitalization Matter?

On a **case-sensitive** filesystem, `Notes.txt` and `notes.txt` can name two different files.
On a **case-insensitive** filesystem, those spellings usually identify the same name even if the system remembers how you capitalized it.

Linux filesystems are commonly case-sensitive.
Windows directories are commonly case-insensitive, but Windows supports case-sensitive directories too, including configurations used with WSL. [@WindowsCaseSensitivity]
macOS commonly uses case-insensitive APFS, but APFS also has explicitly case-sensitive formats. [@AppleFilesystemFormats]

Do not decide the rule solely from the shell's name.
An external drive, network share, or another mounted filesystem can behave differently from your usual home directory.
Use the spelling shown by the directory listing.
That habit prevents surprises when a project moves to another system.

## When a Path Does Not Work

An error is a clue about the request, not an instruction to add administrator privileges.
Start by checking your current location, then list what is actually there.

- **No such file or directory / path not found:** check the starting directory, spelling, capitalization, and drive. The path may exist somewhere else.
- **Not a directory:** a part you tried to enter may be a file. A name ending in `.txt` is usually a file, but inspect it rather than guessing from the extension alone.
- **Permission denied / access denied:** the location may exist, but your account may not have the required access. Return to a directory you own for these examples.

After any failed directory change, ask for your location again.
Do not assume you arrived and run the next command against the wrong directory.
This habit becomes especially important when the commands start modifying files.

## Key Points

- Directories form a tree with a root at the top; your home directory is somewhere below the root.
- A path names a place in the tree. An absolute path starts at a root; a relative path starts at the current directory.
- `.` means the current directory, and `..` means its parent.
- Use `pwd`, `Get-Location`, or bare `cd` in Command Prompt to check your location.
- Listing shows what is in a directory without moving you; changing directories moves where relative paths begin.
- UNIX-style systems have one tree rooted at `/`; Windows has a tree per drive, and drive-relative paths are a trap.
- Spaces, hidden entries, extensions, and capitalization all affect whether the name you type matches the name on disk.

## Level Up

n00bs finish the chapter here.
You can find your location, navigate to a parent or child directory, and return home.
Hackers start connecting the path on the screen to the structure behind it.

Choose an existing project or document folder and sketch three levels of its directory tree.
Write one absolute path and two relative paths to the same file from different starting directories.
Use directory listings to check your predictions without modifying the file.

Open a second terminal tab and change directories in just one tab.
Ask both shells for their location.
Explain why the files are shared but the current directory is not.

Then explore the help for a navigation feature:

- In Bash/zsh, investigate `cd -`, which can return to the previous directory, and the `pushd` and `popd` directory-stack commands. [@BashNavigation; @ZshBuiltins]
- In PowerShell, read about `Push-Location` and `Pop-Location`, which save and restore locations. [@PowerShellLocationStacks]
- In Command Prompt, compare `pushd` and `popd` with `cd`; read about their handling of drive changes and network paths before using them. [@WindowsPushd; @WindowsPopd]
