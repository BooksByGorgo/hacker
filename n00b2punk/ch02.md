# Meet Your Shell

Your terminal is open.
Now we need to know who is listening.

The shell decides what your command means: which words name programs, which characters have special jobs, and how to pass information from one command to another.
Two shells in identical-looking windows can interpret the same line differently.
By the end of this chapter, you will be able to identify your shell, check its version, run a few commands, and enter and leave a shell session deliberately.

## The Shells We Will Use

This book has two main tracks: Bash/zsh and PowerShell.
We will also cover Windows Command Prompt, because you will encounter instructions and tools that use it.

| Shell | Where you will encounter it | How this book uses it |
|---|---|---|
| **Bash** | Linux, macOS, and UNIX-style environments on Windows | A main shell for UNIX command-line work and scripts |
| **zsh** | macOS and systems where it has been installed | A main interactive UNIX shell, with differences from Bash called out |
| **PowerShell** | Windows; PowerShell 7 also runs on macOS and Linux | The main Windows track and its object-based approach to automation |
| **Command Prompt** (`cmd.exe`) | Windows | Native Windows commands and batch-file conventions |

An **interactive shell** reads commands as you enter them.
A **script** stores commands in a file so a shell can run them later.
We start interactively so that you can inspect each result before moving on.

Bash and zsh share much of their everyday command syntax, but they are different programs.
Where an example works in both, we will label it **Bash/zsh**.
Where the behavior differs, we will give separate examples.

Current macOS installations normally use zsh as the default shell in Terminal.
Your account or terminal settings can select another shell. [@AppleDefaultShell]
Linux systems also vary, so we will check rather than assume.

### Two PowerShells on Windows

**Windows PowerShell 5.1** and **PowerShell 7** are separate products.
Windows PowerShell comes with Windows and runs only on Windows; PowerShell 7 is also available for macOS and Linux. [@WindowsPowerShellOverview]

On Windows, `powershell.exe` starts Windows PowerShell, while `pwsh.exe` starts the newer PowerShell when it is installed.
Installing PowerShell 7 does not replace Windows PowerShell 5.1; they can exist side by side. [@PowerShellMigration]

Our main PowerShell track targets PowerShell 7.
The examples in this chapter also work in Windows PowerShell 5.1.
You can start with the version you already have; later chapters will mark examples that require newer features.

::: {.tip}
**Trap:** Updating Windows Terminal does not update the shell running inside it.
The terminal and PowerShell have their own versions.
When comparing your results with a tutorial, check which one the tutorial is talking about.
:::

### Windows Can Host More Than Windows Shells

Windows Subsystem for Linux, or **WSL**, lets you work in a Linux environment on Windows.
A WSL profile in Windows Terminal can therefore start a Linux shell.
The surrounding window still belongs to Windows Terminal. [@WindowsTerminalOverview]

You may also encounter **Git Bash**, the Bash environment supplied with Git for Windows.
It is a different environment from WSL. [@GitForWindows]
Record which environment you are using; it affects available commands and how paths work.
For now, you do not need either one to begin the Windows track.

## Read the Prompt

Here are examples of prompts you might see.
These are illustrations, not commands to type:

```text
student@laptop:~$
student@MacBook ~ %
PS C:\Users\student>
C:\Users\student>
```

The first two are typical UNIX-style prompts.
They show a username, a computer name, and a location; `~` commonly represents your home directory.
The last two resemble default PowerShell and Command Prompt prompts on Windows, including a path to the current directory.

A **directory** is what a graphical file manager calls a folder.
Your shell has a **current directory**, which gives commands a starting place for finding files.
We will explore directories properly in Chapter 5.

Prompts are customizable.
A `$`, `%`, or `>` at the end is a clue, not proof of which shell is running.
A tab title can also be renamed.
Use the checks below to get better evidence.

## Identify the Shell You Are Using

Start with the profile you selected when opening the session.
Then use the section for that shell family.
Do not paste every command below into every shell: they speak different languages.

### Bash and zsh

In a Bash or zsh session on macOS or Linux, run:

```sh
ps -p $$ -o comm=
```

`ps` reports information about running programs, also called **processes**.
Here, `-p` selects a process, and `$$` supplies the current shell's process ID.
`-o comm=` asks for its command name without a column heading.
You might see `bash`, `zsh`, or a name with a leading dash or a path.
The precise display varies by system. [@ProcpsPs]

Once you know which shell you are in, ask for its version.

**Bash:**

```bash
echo "$BASH_VERSION"
```

**zsh:**

```zsh
echo "$ZSH_VERSION"
```

A **variable** is a named value.
These shells provide variables containing their own version information, and the `$` asks the shell to use the value. [@BashVariables; @ZshParameters]
The double quotes keep the value together as one argument.
For now, copy the punctuation exactly; we will study variables and quoting in detail later.

In an ordinary session, the matching variable produces a version string.
The other shell's version variable is usually unset and produces a blank line.
Record the result rather than expecting a particular version number from this book.

::: {.tip}
**Wut:** `echo "$SHELL"` usually reports your configured login shell.
It does not reliably identify the shell currently interpreting your commands.
Starting Bash from zsh can leave `$SHELL` pointing to zsh.
Similarly, `bash --version` checks the Bash program that command finds, even if you are currently using zsh.
:::

### PowerShell

Run this inside PowerShell:

```powershell
$PSVersionTable
```

This displays information about the running PowerShell session.
Look for **PSVersion** and **PSEdition**.
A version beginning with `5.1` and the edition `Desktop` identifies Windows PowerShell 5.1.
A version beginning with `7` and the edition `Core` identifies PowerShell 7. [@PowerShellAutomaticVariables; @PowerShellMigration]

To request just the version, enter:

```powershell
$PSVersionTable.PSVersion
```

The dot selects the named entry from the version table.
PowerShell can display the value of an expression directly, so there is no `echo` in front of this command.

The `$` here is part of the variable name syntax.
Unlike a `$` drawn as part of a UNIX prompt, this one belongs in what you type.

### Command Prompt

Select the **Command Prompt** profile in Windows Terminal, or open Command Prompt from Start.
Its interpreter is `cmd.exe`. [@WindowsCmd]
Run:

```bat
ver
```

This prints the **Windows operating-system version**, not an independent shell version. [@WindowsVer]
Record the shell as Command Prompt (`cmd.exe`) and the Windows version separately.
The distinction matters when you compare a Windows command with an example from another system.

## Say Something, Then Ask Where You Are

We will do the same two tasks in each shell: print a message and display the current directory.
Use the block that matches your session.
Type each line separately and inspect its result before entering the next.

### Bash/zsh

```sh
echo "I am learning to ask better questions."
pwd
```

`echo` writes the message.
The double quotes group its words; they do not appear in this output.
`pwd` stands for *print working directory* and displays your current directory.
For example, a Linux session might show `/home/student`, while a Mac might show `/Users/student`.
Your result depends on where the session started.

### PowerShell

```powershell
Write-Output "I am learning to ask better questions."
Get-Location
```

`Write-Output` sends the message to PowerShell's output stream; in this example, it is displayed in the terminal. [@PowerShellWriteOutput]
`Get-Location` reports the current location.
In a normal filesystem location, its display includes your current directory under a `Path` heading. [@PowerShellGetLocation]

The `Verb-Noun` names are a PowerShell convention.
`Get-Location` tells you that you are getting information about a location.
We will meet more of these commands, called **cmdlets**, in the next chapter.

### Command Prompt

```bat
echo I am learning to ask better questions.
cd
```

Command Prompt's `echo` prints the message.
Its `cd` command, with no argument, displays the current directory. [@WindowsEcho; @WindowsCd]

Notice that we left out the quotes around the message in this version.
For this simple `echo` command, Command Prompt would print those double quotes too.
We will explore how each shell handles quoting in Chapter 9.

::: {.tip}
**Trap:** `cd` alone has different behavior across shells.
In Command Prompt it displays a directory; in Bash and zsh it moves you to your home directory.
Use the example for your shell, even when a command's name looks familiar.
:::

## Familiar Names Can Hide Different Commands

In Chapter 1, `echo console-ready` worked in all four shells.
In PowerShell, `echo` is normally an **alias**, an alternate name for `Write-Output`.
Bash, zsh, and Command Prompt provide their own implementations of `echo`.

PowerShell on Windows also supplies familiar names such as `ls` and `dir` as aliases for `Get-ChildItem`.
That does not give them all the options of UNIX `ls` or Command Prompt's `dir`. [@PowerShellAliases]

We will usually show full PowerShell command names so you can tell what is being used.
Later, you can choose shorter forms for your own interactive work.

This is also why we will spend time on both main tracks.
PowerShell can pass structured values between commands; UNIX tools commonly pass text.
Both let you build useful combinations, but understanding the combinations requires more than memorizing equivalent-looking names.

## Start a Shell from a Shell

A shell is a program, so one shell can start another.
You do not have to change your account's default shell to experiment.

The following names start interactive shells when the programs are installed and can be found:

| Enter this command | What it starts |
|---|---|
| `bash` | Bash |
| `zsh` | zsh |
| `pwsh` | PowerShell 7 on the systems we use in this book |
| `powershell.exe` | Windows PowerShell on Windows |
| `cmd.exe` | Command Prompt on Windows |

Do this in a spare tab.
First identify the shell already running there.
Then start one available shell from the table and check its identity using the matching instructions above.
Starting a second instance of the same shell is fine.

You now have a **parent shell** waiting for a **child shell** to finish.
Your typing goes to the child.
Enter:

```text
exit
```

The child ends, and the parent resumes at its prompt.
Check the shell identity again.
You should be back where you started.

The terminal may look almost unchanged, especially if both shells use the same prompt.
That is another reason to verify which program is interpreting your commands.

If a launch command reports that it cannot be found, that shell may not be installed or may not be in the command search path.
Continue with one that is available.
We will work on installation and command lookup later.

## Errors Are Part of the Conversation

At a fresh prompt, try this deliberately nonexistent command:

```text
hax0r-command-that-does-not-exist
```

With a normal setup, you will get an error saying the command was not found or was not recognized.
The wording differs among shells.
The prompt then returns, and you can enter another command.
You have not damaged the shell; you asked it to find something it could not find.

Run the message command for your shell again.
The error did not prevent the next valid command from working.

When reporting a problem, include the shell and version, the command you entered, and the actual error text.
An error message is evidence about what happened.
"It didn't work" leaves that evidence out.

Sometimes you will see a different prompt because the shell thinks your command is unfinished.
For example, an unclosed quote in Bash, zsh, or PowerShell can make it wait for more input.
To abandon unfinished input in an ordinary interactive session, press `Ctrl+C` with no text selected.
We will practice editing and recovering from these situations in Chapter 4.

## Key Points

- Know which shell is interpreting your commands; a prompt or tab title alone is not proof.
- Windows PowerShell 5.1, PowerShell 7, and Command Prompt are distinct environments.
- Check the running shell's version rather than assuming it matches a tutorial.
- Similar command names can hide different syntax and behavior.
- Starting another shell creates a child session; `exit` returns you to its parent.
- Read error messages and use them to decide what to investigate next.
